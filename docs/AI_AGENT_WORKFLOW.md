# AI / Agent 辅助开发流程

本文档记录本项目中 AI / Agent 参与开发的真实边界，主要用于说明辅助开发过程，而不是把项目描述成全自动生成。

## 参与环节

### 需求拆解

AI / Agent 用于把“考研学习管理”这个需求拆解为更具体的模块，包括学习计时、科目管理、历史记录、学习统计、每日复盘、目标设置和 AI 总结。

### 代码阅读

AI / Agent 辅助阅读 Kotlin、Jetpack Compose、Repository、Room、DataStore、Hilt 等相关代码，帮助梳理页面、状态、数据流和依赖注入结构。

### UI 优化

AI / Agent 用于辅助分析 Jetpack Compose 页面结构，提出组件拆分、状态展示、输入项组织和页面可读性的改进建议。最终是否采纳由人工判断。

### Bug 定位

AI / Agent 用于辅助定位计时状态、状态保存、AI 总结触发、接口配置和构建错误等问题，提供排查路径和可能原因。实际修复需要结合本地运行和人工验证。

### 智能总结流程设计

项目采用“本地规则总结 + 大模型增强”的思路：

- 本地规则总结用于在未配置 API Key 或接口不可用时提供基础总结能力。
- 大模型增强用于在用户配置第三方接口后，对学习记录和复盘内容进行更自然的结构化总结。
- OpenAI-compatible 配置用于降低不同模型服务之间的接入成本。

AI / Agent 参与了该流程的设计讨论和部分实现建议，但不替代人工对隐私、安全和用户体验的最终判断。

### 构建与文档整理

AI / Agent 用于辅助整理 README、Roadmap、发布清单、申请材料建议和构建说明，也用于分析 Gradle / Android 构建报错。

## 人工审核与测试边界

- 人工负责最终代码审核。
- 人工负责运行 App、检查页面和确认功能取舍。
- 人工负责确认 API Key、签名证书、APK、AAB、`local.properties`、`.env` 等敏感或构建产物不进入仓库。
- AI / Agent 生成的建议需要经过人工验证后才能合并。
- 不应把 AI / Agent 辅助过程描述为完全自动开发或完全自动测试。
